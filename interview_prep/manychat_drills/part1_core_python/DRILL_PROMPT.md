## Мої знайдені слабкі місця (холодний прогін 20 питань, 23.5/51)

Треную саме їх:

1. **`*` на послідовності копіює посилання.** `[[0]*3]*3` — це один рядок, показаний тричі.
   *(це вже закрив, перевіряй рідше)*
2. **Late binding у замиканнях.** `[lambda: i for i in range(3)]` → `[2,2,2]`; фікс `lambda i=i:`.
   *(закрив, перевіряй рідше)*
3. **Області: `nonlocal` vs `global`.** `nonlocal` = найближча обгортаюча **функція**, не модуль.
   Присвоєння (`=`, `+=`) робить імʼя локальним на етапі компіляції → `UnboundLocalError`.
   Мутація (`.append`) присвоєнням не є. **ГОЛОВНА ДІРА.**
4. **Argument binding.** Голий `*` у підписі ⇒ все після нього keyword-only; зайві іменовані
   аргументи збираються в `**kw` як **dict**.
5. **`is` vs `==` і контракт hash/eq.** `[] is []` → False, але `() is ()` → True.
   `nan != nan`, проте `[nan] == [nan]` → True (list eq шорткатить по identity).
   `1 == True == 1.0`, хеші однакові ⇒ `{1, True, 1.0, "1"}` має довжину 2; dict перезаписує
   значення, але **зберігає перший обʼєкт ключа**.
6. **Створення ≠ виклик.** Найглибша діра. Я читав `append(lambda: x)` як «поклали результат»,
   а не «поклали функцію». Дужки = виклик, без дужок = значення, `@` = виклик під час `def`.
   Сюди ж: `async def f()` повертає **coroutine object** і нічого не виконує до `await`.

**Патерн моїх помилок:** я сильний, коли механізм схований у **структурі** коду, і слабкий, коли
він схований у **часі** — коли саме виконується декоратор, коли компілятор вирішує, що імʼя
локальне, коли відпрацьовує `finally` в генераторі. Дави на «коли», не лише на «що».

**Дві звички, які коштували мені більше за незнання:**
